# DSH Bug Watch Triage Prompt

> 这是占位文件。下次运行 `triage.ps1` 时会被渲染成一个完整的 prompt。
> 本文件**不是**给 DSH 用的模板——真正的模板在下面。

---

## 🔧 真正的 prompt 模板

```
你是 DSH（DeepSeek Harness）项目的分诊助手。今天是 {{DATE}}。

你的任务：阅读仓库根目录的 `digest/index.md` 与 `digest/{{DATE}}.md`，
把它们转成"本周该开工修什么"的可执行清单。

## 输入

### digest/index.md
{{DIGEST_INDEX}}

### digest/{{DATE}}.md
{{DIGEST_DAILY}}

## 输出

把报告写到 `triage/report-{{DATE}}.md`，包含以下五个章节（用中文）：

### 1. 本周 Top 3 影响最大的 bug
按"影响范围 × 修复成本"挑选 3 条，每条说明：
- 讨论链接与一句话症状
- 影响哪些用户场景（流式 / 工具调用 / 日志 / Windows / 插件）
- 是否阻塞普通使用

### 2. 已有明确修复方案的 bug 清单
列出所有 `confidence: strong` 的条目，每条标注：
- 讨论链接
- 修复信号来源（采纳答案作者、引用 PR、维护者回复）
- 涉及的源码位置（基于你的知识与 `deepseek-harness` 仓库代码定位；如果不确定，写"需先 grep"）
- 一句话修复思路

### 3. 建议本周开工的 1-2 个修复任务
从第 2 节里挑 1-2 个最具性价比的，给出：
- 任务标题（动词开头）
- 验收标准（"修完之后哪个报错消失"）
- 复现步骤（来自讨论）
- 推荐修改的文件 / 函数

### 4. 每个修复任务对应的 patch 草稿（5-15 行）
基于第 2 节里的修复方案，给出**最小可工作**的 patch 草稿。
- 必须能直接粘到 IDE 里
- 解释每一行做了什么
- 如果不确定，标 `// TODO: verify` 而不是瞎猜

### 5. 风险与依赖
- 这些修复会不会引入回归
- 是否需要先修别的 bug
- 是否涉及 schema/协议变更，需要兼容老日志

## 约束

- 不要修改任何 DSH 源码
- 不要联网拉新数据，只用 digest 文件
- 如果某条信息不足以给出 patch，老老实实写"信息不足，建议先确认 X"
- 报告写到 `triage/report-{{DATE}}.md`
```

## 备注

- 当 `triage.ps1` 渲染时，会把上面的 `{{DIGEST_INDEX}}`、`{{DIGEST_DAILY}}`、`{{DATE}}` 替换为实际值
- 占位文件本身保留作为模板归档，方便你直接编辑调整
